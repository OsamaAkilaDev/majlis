# Stage 2 — Auth & Users Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship signup, login, refresh rotation with reuse detection, logout, a fail-closed session guard, a database-derived permission guard, user suspension, and the in-transaction audit writer — all tested against a real PostgreSQL 18.

**Architecture:** Two global guards registered as `APP_GUARD` mean every endpoint is protected unless it opts out with `@Public()`. The access token is a stateless 15-minute JWT carrying `{ sub, iat, exp }` and nothing else; the session guard reloads the user from the database on every request, which is what makes suspension and appointment loss take effect immediately. Refresh tokens are opaque 256-bit randoms stored only as SHA-256 hashes, rotated under a row lock, with reuse of a rotated token revoking the whole family. Permission evaluation is a pure function over facts the guard loads, so the matrix is unit-testable without a database. Every write goes through `TransactionHost`, so the audit row and the action it records share one transaction structurally.

**Tech Stack:** NestJS 12.0.1 · `@nestjs/jwt` 12.0.1 · `@node-rs/argon2` 2.2.0 · `@nestjs/throttler` 6.5.0 · `cookie-parser` 1.4.7 · Prisma 7.10.0 · Zod 4.5.4 · Vitest 5.0.0 · PostgreSQL 18

**Spec:** [`docs/specs/2026-09-11-stage-2-auth-design.md`](../../specs/2026-09-11-stage-2-auth-design.md) — read it before Task 1. Its parent is [`docs/specs/2026-09-10-majlis-design.md`](../../specs/2026-09-10-majlis-design.md).

## Global Constraints

Copied verbatim from `CLAUDE.md` and the spec. Every task's requirements implicitly include this section.

- **Write through `TransactionHost`, never `PrismaService`.** `host.tx` is the ambient transaction; `host.run(fn)` starts one or joins the caller's. An ESLint rule enforces this — `PrismaService` cannot be imported as a value outside `apps/api/src/prisma/`. If you find yourself wanting to disable that rule, you have the wrong design.
- **Services throw `DomainError` subclasses**, never `@nestjs/common` exceptions. `NotFoundError` · `ForbiddenError` · `ConflictError` · `UnprocessableError` · `UnauthorizedError` (added in Task 3). The global filter renders RFC 9457 Problem Details.
- **Server-side authorization on every protected endpoint**, re-derived from the database per request. Never trust a client-supplied role, club ID, or ownership claim.
- **No secrets in code or logs.** No raw refresh token, password, QR token, or session token is stored or logged anywhere. Refresh tokens are stored as SHA-256 hashes only.
- **Pin every version exactly.** Never `latest`.
- **Never pin a package published in the last 48 hours.** pnpm 11 refuses it. **Do not add a `minimumReleaseAgeExclude`.** This is why `@node-rs/argon2` pins to `2.2.0` and not `2.2.1` (published 2026-09-10, too recent).
- **Verify every version exists on npm before pinning.** The Stage 1 plan contained versions that never did.
- **CommonJS, not ESM.** Do not add `"type": "module"` to `apps/api/package.json`. This is why `@nestjs/jwt` is used rather than `jose`.
- **Use the `API_PREFIX` constant**, never the literal `/api/v1`. Its leading slash is load-bearing.
- **`user` is a reserved word in Postgres.** Quote it in raw SQL: `FROM "user"`.
- **All timestamps are `timestamptz`, stored UTC.**
- **English only.** No localisation fields.
- **Every test must name the broken implementation it catches.** Before trusting a test, state which wrong code it would turn red against. If you cannot name one, the test is not testing anything. Proving it by deliberately breaking the implementation and watching the test fail is cheap and expected.
- **`pnpm --filter @majlis/api test:integration` needs PostgreSQL 18 running** on `localhost:5432` with the `majlis_test` database. `pnpm db:check` confirms connectivity.
- Every task ends with a passing test run and a commit. Conventional commit messages.

```ts
import { randomUUID } from 'node:crypto';

/**
 * A value unique to this call. Integration tests share one database and
 * truncate between tests, but a collision inside a single test is still
 * possible with a fixed string — and a unique-constraint failure in setup
 * reads like a bug in the code under test.

export function uniq(prefix: string): string {
  return `${prefix}-${randomUUID().slice(0, 8)}`;
}

    fullName: 'Test Person',
    ...overrides,

}
```

- [ ] **Step 4: Implement**

```ts
import { Injectable, type NestMiddleware } from '@nestjs/common';
import { AsyncLocalStorage } from 'node:async_hooks';

export interface RequestFacts {
  requestId: string;
  ip?: string;
  userAgent?: string;
}

/**
 * Ambient per-request facts. `audit_log.request_id` is NOT NULL, and `ip` is
 * wanted, but threading both through every service signature would put two
 * parameters on every method in the codebase for the benefit of one writer.
 *
 * This mirrors TransactionHost deliberately: the codebase then has one
 * pattern for ambient context rather than two. A Nest REQUEST-scoped
 * provider was rejected — request scope propagates up the injection graph,
 * so one request-scoped audit service makes every service that consumes it
 * request-scoped too.
 */
@Injectable()
export class RequestContext {
  private readonly storage = new AsyncLocalStorage<RequestFacts>();

  get current(): RequestFacts | undefined {
    return this.storage.getStore();
  }

  run<T>(facts: RequestFacts, fn: () => T): T {
    return this.storage.run(facts, fn);
  }
}

@Injectable()
export class RequestContextMiddleware implements NestMiddleware {
  constructor(private readonly context: RequestContext) {}

  use(req: { id?: string; ip?: string; headers: Record<string, unknown> }, _res: unknown, next: () => void): void {
    this.context.run(
      {
        // pino-http's genReqId already set this and echoed it in the
        // x-request-id response header, so a log line and an audit row for
        // the same request carry the same id.
        requestId: String(req.id ?? 'unknown'),
        ip: req.ip,
        userAgent: typeof req.headers['user-agent'] === 'string' ? req.headers['user-agent'] : undefined,
      },
      next,
    );
  }
}
```

```ts
    consumer.apply(RequestContextMiddleware).forRoutes('*');
  }
```

- [ ] **Step 1: Write the failing test that defines the guarantee**

Catches: an audit writer that injects `PrismaService` (or otherwise escapes the ambient transaction), which would leave an audit row claiming an action that was rolled back. The ESLint rule from the previous commit blocks the obvious way to write that bug; this test blocks the rest.

```ts

  const host = app.get(TransactionHost);
  const audit = app.get(AuditService);
  const user = await prisma.user.create({ data: aUser() });

  await expect(
    host.run(async () => {
      await host.tx.user.update({ where: { id: user.id }, data: { fullName: 'Changed' } });
      await audit.record({
        action: 'user.updated',
        entityType: 'User',
        entityId: user.id,
        outcome: 'SUCCESS',
      });
      throw new Error('the action failed after the audit row was written');
    }),
  ).rejects.toThrow('the action failed');

  expect(await prisma.auditLog.count({ where: { entityId: user.id } })).toBe(0);
  expect((await prisma.user.findUniqueOrThrow({ where: { id: user.id } })).fullName).toBe(
    'Test Person',

it('writes the row when the action commits', async () => {
```

```ts
import { TransactionHost } from '../prisma/transaction.host';

/**
 * Writes through host.tx, so a row enlists in whatever transaction the caller
```

```ts
/**
 * The matrix is data. Later stages add rows; neither this function nor the
 * guard changes. Stage 2 needs exactly two.
 *
 * ADMIN is listed explicitly in every rule that admits it. There is
 * deliberately no `if (platformRole === 'ADMIN') return true` shortcut — see
 * the test above and Stage 2 design §5.3.
 */
export const PERMISSIONS = {
  'user:list': { platform: ['ADMIN'] },
  'user:suspend': { platform: ['ADMIN'] },
} as const satisfies Record<string, PermissionRule>;

export function evaluate(permission: Permission, facts: ActorFacts): boolean {
  const rule = (PERMISSIONS as Record<string, PermissionRule>)[permission];
  // Unknown permission denies. A typo in a decorator must fail closed.
  if (!rule) return false;
  return matches(rule, facts);
}

export function matches(rule: PermissionRule, facts: ActorFacts): boolean {
  if (rule.platform?.includes(facts.platformRole)) return true;
  if (rule.club?.some((r) => facts.clubRoles.includes(r))) return true;
  if (rule.event?.some((r) => facts.eventResponsibilities.includes(r))) return true;
  return false;
}
```

```ts
@Injectable()
export class SessionGuard implements CanActivate {
  constructor(
    private readonly reflector: Reflector,
    private readonly tokens: TokensService,
    private readonly host: TransactionHost,
  ) {}

  async canActivate(ctx: ExecutionContext): Promise<boolean> {
    const isPublic = this.reflector.getAllAndOverride<boolean>(IS_PUBLIC_KEY, [
      ctx.getHandler(),
      ctx.getClass(),
    ]);
    if (isPublic) return true;

    const req = ctx.switchToHttp().getRequest();
    const token = req.cookies?.[SESSION_COOKIE];
    if (!token) throw new UnauthorizedError('Not signed in.');

    const userId = await this.tokens.verifyAccessToken(token);

    // Loaded on EVERY request. This is what makes suspension and appointment
    // loss take effect on the next request rather than at token expiry.
    // Do not cache it. Do not move any of it into the token.
    const user = await this.host.tx.user.findUnique({ where: { id: userId } });
    if (!user || user.status !== 'ACTIVE') throw new UnauthorizedError('Not signed in.');

    req.actor = user;
    return true;
  }
}
```

```ts
async refresh(raw: string): Promise<AuthResult> {
  return this.host.run(async () => {
    const hash = this.tokens.hashRefreshToken(raw);

    // Lock first, read through Prisma second. The raw query locks exactly one
    // row (token_hash is unique) without forcing a hand-written snake_case
    // mapping; the findUnique that follows returns the camelCase model.
    const locked = await this.host.tx.$queryRaw<{ id: string }[]>`
      SELECT "id" FROM "refresh_token" WHERE "token_hash" = ${hash} FOR UPDATE`;
    if (locked.length === 0) throw new UnauthorizedError('Session expired.');

    const row = await this.host.tx.refreshToken.findUniqueOrThrow({
      where: { id: locked[0]!.id },
    });

    if (row.revokedAt || row.replacedById) {
      // REUSE. We cannot tell the thief from the victim, so neither keeps the
      // session. Revoking the family is the entire point of rotation.
      await this.host.tx.refreshToken.updateMany({
        where: { familyId: row.familyId, revokedAt: null },
        data: { revokedAt: new Date() },
      });
      await this.audit.record({
        action: 'auth.refresh.reuse_detected',
        entityType: 'RefreshToken',
        entityId: row.id,
        outcome: 'DENIED',
        actorUserId: row.userId,
        reason: 'A rotated refresh token was presented again.',
      });
      throw new UnauthorizedError('Session expired.');
    }

    if (row.expiresAt <= new Date()) throw new UnauthorizedError('Session expired.');

    const user = await this.host.tx.user.findUnique({ where: { id: row.userId } });
    if (!user || user.status !== 'ACTIVE') throw new UnauthorizedError('Session expired.');

    const successor = await this.mintFamilyMember(user.id, row.familyId);
    await this.host.tx.refreshToken.update({
      where: { id: row.id },
      data: { revokedAt: new Date(), replacedById: successor.id },
    });

    return { user, accessToken: await this.tokens.signAccessToken(user.id), refreshToken: successor.raw };
  });
}
```

Every failure path returns the same message and the same status. The client cannot distinguish expiry from reuse from an unknown token, and does not need to.

Logout revokes the presented token's whole family and clears both cookies, and returns 204 whatever it finds — no cookie, unknown token, already revoked. A user who cannot log out is a worse outcome than a redundant no-op.
